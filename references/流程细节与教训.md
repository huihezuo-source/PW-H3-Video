# 流程细节与教训

每条教训都来自真实返工，括号里是出事的片子。

## 1. 规划

- 长故事先压成一条主线，只留推动主线的场景，其余砍掉。写清“砍掉了什么”，避免中途又加回来。
- 分段按 H3 单段上限（约 15 秒）切，每段只做一件事。
- 每段标注类型：旁白段 / 对白段。旁白段生成时整段无台词。
- 写台词表之前先做剧本一致性检查：同名不同人、代词指代乱、行为归属错位（上一段说走了的人下一段又在说话）。每条记问题、涉及角色、位置、改法，改完原文再拆段。这一步借自开源短剧工作台 Jellyfish 的一致性检查员，它只查这三类，查完就停。
- 每段除台词外再记一行镜头信息：景别 / 机位 / 运镜、时间 / 氛围 / 情绪、动作拍点、在场实体、本段临时状态（淋湿、受伤、脏污）、上一段结尾怎么接本段开头。首帧提示词和 H3 提示词都从这一行抄，不临场发挥。角色、场景、道具各有一张实体表，记固定描述、变体和出现段，名字在所有提示词里原样保留。
- 写“本次要验证的新做法”表，每条写清“怎么算有效”，复盘时逐条打分。
- 写“已知风险”：多人同框容易多手、走样，群戏用远景；拟人动物的脸比真人难保持一致；特效画面（巨大的脸、天空塌下）可能生成不好，准备代码合成兜底。

## 2. 基调与风格（教训：黑暗故事里出了一组干净的偶像脸）

在任何提示词之前写下：

- **光：** 几个光源、从哪来、什么颜色、暗部占多少。
- **色：** 主色和饱和度，唯一的高对比留给哪个瞬间。
- **质感：** 衣物新旧、脏污、潮湿；皮肤要不要美化。
- **表情：** 不安、警惕、空洞，还是轻松。
- **背景：** 母版也放在这个世界里，不用纯色背景。

然后为每个角色写一行设计要点，3–4 个不变锚点（例如：额角银鳞、九颗骷髅项链、暗沉金箍）。

## 3. 配音

- 先试 2–3 种音色让人挑，选定后用这一段做参考音克隆，后面所有旁白都用它，音色才统一。
- 每条出来都用 `asr.py` 转写，核对一字不差（同音字可接受）。
- 量真实时长，按真实时长定镜头，不按估算。
- 需要露脸说话的角色和旁白是同一人时，把旁白音频作为 H3 的参考音，两边声音才一致。

## 4. 角色母版

- 正面全身图是唯一的根，其他视图都参考它。坏一张单独重出，不整批重来。
- 一次出 2 张挑 1 张，比反复改提示词快。
- 局部问题用编辑模型改（去掉饰品、改发型），提示词后面固定接一句“其余全部保持不变”。
- 编辑模型容易“改过头”：让它去掉头饰，它可能把头发也剃了。改完要和原图并排看。
- 换装出新版本文件，旧图不覆盖。

## 5. 首帧（教训：缩略图检查漏了残留的猫爪和闭错的眼睛）

- 只到动作刚开始的未完成态，后面交给视频模型。
- 说话双方面朝对方。
- 放大到原分辨率逐项看：手/爪、眼睛睁闭、嘴、饰品、多余物体、人数。
- 和母版并排发给用户确认。**确认前不生成视频。**

首帧提示词怎么写（参考开源短剧工作台 Jellyfish 的分镜提示词约束，2026-11 整理）：

- 固定顺序：景别和机位 → 场景环境 → 主体人物和关键物件 → 动作状态 → 氛围情绪 → 风格收束。每张首帧都按这个顺序写，跨段才像同一部片。
- 首帧只写"触发瞬间"或"最初反应"：刚抬手、刚转头、正要开口。不写完成态、最终姿态、情绪爆发后的结果，那些是视频模型的活。有连续动作链时用"刚开始 / 尚未完成 / 被打断"这类未完成态的说法。
- 尾帧（做首尾帧控制时）写收束：动作停在哪、人物最后的姿态、视线落在哪、情绪余韵。
- 承接相邻段：看规划表里"上一段结尾 → 本段开头"那一列，本段首帧要接着上一段的动作、空间方向、视线和情绪，不要像新场景重新开局；同时给下一段留一个自然的收束，避免硬切。
- 人物的左右关系、朝向、视线落点、反打轴线不翻转。上一段甲在左乙在右，这一段不要无故调换。
- 写清主体在画面里的位置和朝向（画面左三分之一、背对镜头、侧身四分之三），减少构图突变。
- 规划里的角色、场景、道具名字原样写进提示词，不翻译、不换同义词、不另起描述。
- 只突出主角色、主场景、主动作。其他在场的元素只有在强化这个画面时才写，不为了"写全"平均罗列所有人和道具。
- 有导演指令（用户明确要求的画面）时，它优先于以上所有条。

## 6. 生成（H3）

- 提示词结构用官方格式（integrated_multimodal_description / overall_soundscape / non_diegetic_music）。
- 每句台词写清：谁说、看向谁、听者嘴闭合。单人镜头把对方写成画外某方向。
- 只写常见动作，不写精确的物理交互；开场要有主体运动。
- 改动作时连声音描述一起改，声音词也会驱动画面。
- 首帧用 AddGuide 锚定到第 0 帧，Ref2VA 本身不保证还原首帧。
- 换人（Character Swap LoRA）时，每段最多含一个硬切，否则切点后会变回原角色。

## 7. 检查（教训：旁白被安到了画面里的角色嘴上，稀疏抽帧没发现）

- **逐句说话人：** `speaker_grid.py` 按台词表每句出一张密集网格（默认每 0.25 秒一帧），回答“谁的嘴在动”。
- **视线：** 每句抽一帧看视线，不只看嘴。
- **接缝：** 相邻两段一起看，查尾帧和首帧、音频是否断。
- **人数：** 长段里可能长出第二个同样的角色，密集扫一遍。
- **检查用封闭题：** 不问“有没有问题”，逐项单选；发现一处，查全片同类问题。每条结论指到句子和时间码。

## 8. 后期

- 放大：只放大通过的版本（RealESRGAN x2 再缩放到目标尺寸）。
- 帧率：H3 输出 24 fps，需要回原片帧率时每段先插帧再按原帧数对齐，不要整片一起裁，否则会漂移几帧。
- 字幕：台词逐字来自台词表。
- 响度：两遍 loudnorm，目标 -14 LUFS、真峰值 -1.5 dBTP。
- 封面：3:4 和 9:16 各一版，上方压暗放标题。
- 交付后清理：每集只留成片和封面，共享素材放公共目录。

## 9. ComfyUI 运维

- 进度事件只发给提交任务的那个 client_id。用别的 id 监听什么都收不到，会误以为卡死。
- 在模型加载阶段发 /interrupt 可能让任务挂住，只能重启 ComfyUI。
- 同一张卡上如果还有本地大模型在跑，会占显存，出图速度能慢十倍。
- 显存不够时 TTS 节点开 force_offload。
